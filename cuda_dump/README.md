# TileKernels CUDA Source Dump

This directory contains CUDA C sources generated from every `@tilelang.jit` factory in [`tile_kernels/`](../tile_kernels/). Each file is a **canonical specialization**: one compile-time parameter set per JIT factory, matching defaults used in the project test suite.

## Prerequisites

- NVIDIA CUDA GPU (SM90/SM100 recommended)
- Python 3.10+
- TileLang (pre-installed in the project environment)
- PyTorch with CUDA support

From the repository root:

```bash
cd /mounted_home/work_code/TileKernels
export PYTHONPATH=$PWD:$PYTHONPATH
```

If editable install works in your environment: `pip install -e .`

## Regenerate all CUDA sources

```bash
python scripts/dump_cuda_sources.py
```

The script:

1. Discovers all `tile_kernels/**/*_kernel.py` modules
2. Finds every `@tilelang.jit`-decorated factory via `tilelang.jit.JITImpl`
3. Compiles each factory with canonical args from `scripts/dump_cuda_sources.py`
4. Writes `.cu` files under `cuda_dump/tile_kernels/`
5. Updates [`manifest.json`](manifest.json) and [`MANIFEST.md`](MANIFEST.md)

Set `TILELANG_PRINT_ON_COMPILATION=0` (default in the script) to suppress compile noise.

## How TileLang exposes CUDA C

TileLang lowers each TileLang program through TVM passes and emits CUDA during compilation. After codegen, the compiled kernel exposes its source string:

```python
compiled = jit_factory(*compile_args, **compile_kwargs)
cuda_source = compiled.get_kernel_source()
```

This is equivalent to:

```python
cuda_source = jit_factory.get_kernel_source(*compile_args, **compile_kwargs)
```

See the [TileLang debug tools tutorial](https://github.com/tile-ai/tilelang/blob/main/docs/tutorials/debug_tools_for_tilelang.md) for related mechanisms:

| Method | Purpose |
|--------|---------|
| `JITKernel.get_kernel_source()` | Primary dump API used here |
| `TK_PRINT_KERNEL_SOURCE=1` | Runtime hook in many kernel launchers; prints source on first compile |
| `@register_cuda_postproc_callback` | Intercept/modify CUDA after codegen |
| `@tilelang.jit(debug_root_path=...)` | Auto-write kernel source during compile (not used here) |

## Output layout and naming

Directory structure mirrors `tile_kernels/`:

```text
cuda_dump/
├── README.md
├── manifest.json
├── MANIFEST.md
└── tile_kernels/
    ├── moe/
    ├── quant/
    ├── mhc/
    ├── engram/
    └── transpose/
```

| Python source | CUDA output |
|---------------|-------------|
| One `@tilelang.jit` in file | `{name}_kernel.cu` (`.py` → `.cu`) |
| Multiple `@tilelang.jit` in file | `{name}_kernel__{factory_name}.cu` |

Examples:

- `tile_kernels/moe/topk_gate_kernel.py` → `cuda_dump/tile_kernels/moe/topk_gate_kernel.cu`
- `tile_kernels/mhc/norm_fn_kernel.py` (6 factories) → `norm_fn_kernel__mhc_pre_norm_fn_fwd_mul.cu`, etc.
- `tile_kernels/engram/engram_gate_kernel.py` → `engram_gate_kernel__get_engram_gate_fwd_kernel.cu`, `...__get_engram_gate_bwd_kernel.cu`

**Skipped:** `tile_kernels/quant/per_channel_cast_kernel.py` is a wrapper with no JIT factory (delegates to `per_channel_cast_fused`).

## Correlating a `.cu` file back to Python

Each `.cu` file begins with a header comment block:

```c
// TileKernels CUDA dump (generated by scripts/dump_cuda_sources.py)
// Source Python: tile_kernels/moe/topk_gate_kernel.py
// JIT factory: get_topk_gate_kernel
// prim_func: topk_gate_kernel
// Compile args: {"args": [72, 6], "kwargs": {}}
// Public API: tile_kernels.moe.topk_gate
```

For machine-readable lookup, use [`manifest.json`](manifest.json) (one entry per `.cu` file):

```json
{
  "cuda_file": "tile_kernels/moe/topk_gate_kernel.cu",
  "source_py": "tile_kernels/moe/topk_gate_kernel.py",
  "jit_factory": "get_topk_gate_kernel",
  "prim_func": "topk_gate_kernel",
  "compile_args": {"args": [72, 6], "kwargs": {}},
  "public_api": "tile_kernels.moe.topk_gate"
}
```

Human-readable table: [`MANIFEST.md`](MANIFEST.md).

### Mapping layers

```text
Public API (e.g. tile_kernels.moe.topk_gate)
    └── calls JIT factory (e.g. get_topk_gate_kernel)
            └── returns @T.prim_func (e.g. topk_gate_kernel)
                    └── lowers to CUDA in .cu file
```

mHC kernels often have no same-file public wrapper; they are invoked from `tile_kernels.modeling.mhc.ops.*` (listed in manifest `public_api`).

## Canonical compile parameters

One specialization per JIT factory. Representative values (from tests):

| Domain | Canonical values |
|--------|------------------|
| MoE | `num_experts=72`, `num_topk=6`, `hidden=7168`, `num_sms=device SM count` |
| Quant | `hidden=7168`, `fmt='e4m3'`, `num_per_channels=128`, BF16 input |
| Engram | `hidden_size=7168`, `hc_mult=4`, contiguous tensor strides |
| mHC | `mhc_mult=4`, `hidden_size=7168`, `mhc_hidden=28672`, `n_splits=16` |
| Transpose | `shape % 128 == 0`, `dtype=bfloat16` |

Different compile-time args produce different CUDA. To dump another specialization, add an entry to `CANONICAL_SPECS` in `scripts/dump_cuda_sources.py` and re-run.
